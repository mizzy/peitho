# peitho

An HTML-native presentation tool with Markdown as the source of truth. The authoritative design reference is `docs/PEITHO_KICKOFF.md` (the kickoff spec). When in doubt about a design decision, check §18 "Undecided Items" in the spec; for new decisions not covered there, check with the author.

## Language

All written artifacts in this project must be in English. This includes: documentation (README, docs/, inline comments, commit messages), GitHub issues (titles and bodies), pull requests (titles, bodies, and review comments), and code identifiers. Do not write these in Japanese or any other language. If the author writes to you in Japanese, still produce artifacts in English.

## The three pillars (invariants that must not be broken)

1. **Separation of content and design**: Content is Markdown, design is layout HTML+CSS. Do not mix them
2. **Version-controllable HTML/CSS layouts**: The layout itself is the schema (`<slot name accepts arity>`). Do not split the contract into a separate file
3. **Type-checked slot contracts and keyed overrides**: Slot excess/deficiency, type mismatches, broken references, and unassigned content are all build errors with line numbers + help. **Silent dropping is absolutely forbidden** (never let the parser swallow unknown structures with `_ => {}`)

Other invariants:
- typestate `Parsed→Mapped→Checked→Rendered`. Phase constructors are private within the crate. An unchecked deck cannot be passed to the renderer (pinned down by a compile_fail doctest)
- Multiple layouts use hybrid dispatch (type-driven approach from §18 adopted at the author's discretion, 2026-07-03): explicit `{"layout":"name"}` > unconditional if there's only one > unique structural match. Ambiguous or zero matches are never silently resolved — they are build errors. Slides carry their own Layout from Mapped onward, so no lookup-failure path is created downstream
- Syntax highlighting is done at build time with syntect (adopted 2026-07-03). Output is spans with `hl-*` classes, colors come from the theme CSS. Custom syntaxes come from `syntaxes:` frontmatter or `syntaxes/` next to the deck and augment the built-in set. Unknown language tags are a parse-time error with a line number (no tag means plain text)
- Deck-level settings ride in YAML frontmatter at the top of the deck (author decision 2026-07-03: "zero-config, settings live in Markdown frontmatter"). Supported keys: `time` (planned presentation time, `15m`/`90s`/`1h30m`/bare integer minutes), `aspect_ratio`, `resolution` (PDF-only physical page size, `WxH` CSS px), `breaks` (single newlines in slide body Markdown render as hard line breaks when `true`), `lang` (BCP 47 deck language, default `en`, emitted as `<html lang>` on every page that renders slides — distribution index, PDF, lint, present, preview, presenter; the remote controller and preview error page stay `en`), `layouts`, `css`, `syntaxes`, `fonts`, and `code_images`. For asset keys, asset resolution is explicit frontmatter > deck-adjacent auto-detect (`layouts/` / `css/` / `syntaxes/` / `fonts/`) > built-in embed/default for layouts/css/syntaxes or no extra asset for fonts; explicit non-existent paths are line-numbered build errors, not silent fallback. Asset values may be a file or a directory: layouts/css/syntaxes read `*.html`, `*.css`, and `*.sublime-syntax` in deterministic filename order, while fonts are copied verbatim without an extension filter so `.woff2`, `.ttf`, and `@font-face` CSS files can sit side by side. The frontmatter body is restricted to flat `key:` lines, plus one nested `code_images:` mapping level (trailing style blank lines allowed); unknown keys, invalid values, markdown swallowed by a missing closing `---`, a leading `---` without valid frontmatter, and settings anywhere but the top are all line-numbered build errors with help — no silent path exists. Validation happens once at `PlannedTime`'s construction (nonzero, overflow, ≤ `Number.MAX_SAFE_INTEGER` so JSON.parse can't round it), and the validated newtype rides on `Deck<P>` through every phase; milliseconds appear only at consumption boundaries (manifest). Design records: `docs/specs/2026-07-03-time-tracking-design.md`, `docs/plans/2026-07-05-frontmatter-layouts-css.md`
- code_images renderer resolution (2026-08-05, Issues #252/#287/#395/#398/#399): Mermaid is built in via `merman`, math via `katex-rs`, and a bare `embed` block resolves exactly one typed author URL. X status URLs retain byte-identical screenshot/card paths; absent or explicit `mode=screenshot` uses the existing build-time PNG, while `mode=card` fetches raw X oEmbed JSON and produces `FragmentKind::EmbedCard { html }`. Every other HTTP(S) URL becomes a normalized `EmbedTarget::Generic`; exact or subdomain hosts of `x.com`/`twitter.com` that are not supported status URLs keep the X-form error and never reach discovery. `mode=` is X-only and is a line-numbered error on generic targets. Generic dispatch uses separate `OEmbedFetcher` operations for the discovery page, discovered JSON endpoint, and thumbnail, and X/generic paths must never touch one another's operations. Discovery is attribute-based JSON oEmbed `<link>` parsing with entity-decoded, RFC 3986-resolved hrefs; provider HTML is never retained or injected. Generic JSON and thumbnail bytes use distinct page-URL cache domains under `.peitho/embeds-cache/`; regular-file/size/magic gates, atomic writes, and self-heal apply, discovery HTML is never cached, and complete hits need neither curl nor Chrome. A generic response with a thumbnail (or a photo `url` fallback) becomes `FragmentKind::GenericEmbedCard { image: Some(_) }`; otherwise it becomes the author-approved text-card fallback with `image: None`. Both variants are `Accepts::Blocks`; the optional typed image must pass through `ImageResolver` and publish-contamination checks before rendering, and all retained strings are escaped with the normalized author URL as permalink. CLI X card misses keep the exact direct, no-redirect `publish.x.com` curl argv; generic fetches alone follow at most five HTTP(S) redirects with operation-specific caps. `dot`, `plantuml`, and every other diagram tag stay user-declared external commands. `CodeImagesConfig::renderer_for(tag)` is the single typed resolver (`External(&CodeImageCommand)` for explicit non-embed frontmatter, `ExternalEmbed(&CodeImageCommand)` for an explicit `embed` override, `BuiltinMermaid` for bare `mermaid`, `BuiltinMath` for bare `math`, `BuiltinEmbed` for bare `embed`, `None` otherwise). Both parser unknown-language validation and `code_images` transformation must go through that resolver — no tag-string carve-outs. `SvgRunner` remains only "run an external command"; external commands and built-in Mermaid use the SVG path (validate → normalize → cache → image fragment), built-in math uses `MathRenderer`/`MathOutput`, screenshot embeds use `EmbedRenderer`, and cards use typed body paths. Explicit `code_images.embed: ...` rejects `mode=` fence options; with a bare `embed` fence it receives the complete block body verbatim and returns to the external SVG/image path. Bare `true`/`false` `code_images` values remain line-numbered errors. Decks with math prepend embedded KaTeX CSS and write `katex-fonts/`; decks without math emit neither. Decks with X or generic cards prepend only the required embedded card CSS in stable order; decks without cards emit none, and decks with neither preserve existing CSS bytes.
  Embed modifiers are typed whitespace-separated `key=value` fence-info tokens. Valid X screenshot and raw oEmbed JSON cache hits need neither Chrome nor network, corrupt X cache entries self-heal, X card HTML is regenerated only from validated, escaped JSON data, and X-card-only decks never invoke Chrome.
- code_images SVG intrinsic size (2026-07-12, Issue #261): every SVG written to `.peitho/code-images-cache/` carries usable absolute `width`/`height` on the root tag — mermaid-style output (`width="100%"`, no height, viewBox only) collapses to 0×0 via `<img>` otherwise. Normalization happens once at the cache-write seam (viewBox supplies missing/unusable dimensions; graphviz output passes through byte-identical); cached files lacking the invariant are cache misses (self-heal); no-dims-no-viewBox and root-tag-not-found are distinct line-numbered build errors. Attribute names match exact case (XML semantics — browsers ignore `WIDTH`/`viewbox`, so peitho must too). User-referenced `![](foo.svg)` assets stay verbatim by design. Design record: `docs/plans/2026-07-12-code-images-svg-intrinsic-size.md`
- SVG Markdown images (2026-09-24, Issue #655): `svg` is a supported Markdown image extension. `resolve_image_paths` (the only Raw→Resolved image transition, so Markdown images and `code_images` output alike) reads every `.svg` asset and requires a locatable root `<svg>` that declares `xmlns="http://www.w3.org/2000/svg"` (Chrome shows a broken `<img>` otherwise) and carries usable absolute `width`/`height` — the same size predicate as the code-images cache; not-SVG, root-not-found, missing-namespace, and no-intrinsic-size are distinct line-numbered build errors. `check_image_svg` is the single "fit for `<img>`" predicate: the code-images cache validity check uses it too, and the code-images output seam rejects a namespace-less command/Mermaid SVG before the cache write with a code-image error naming the tag, so the resolve-time error only ever names an authored file. It is a root-tag inspection, not an XML parser (malformed XML is a known limit). The author's file is never rewritten (the `dist/` copy is byte-identical), it stays `<img>` so SVG scripts never run, and its text draws with system fonts (documented). SVGs referenced directly by layout HTML are not checked (the layout author owns that element's sizing). Design record: `docs/plans/2026-09-24-svg-markdown-images.md`
- Agenda sections (2026-07-04): a slide's page settings comment may declare `{"section":"Name","time":"1m"}` (section and time must appear together; the marked slide starts a section that runs until the next marker). Ranges are derived at parse end; if any marker exists the first slide must carry one; when frontmatter `time` is present the section total must equal it, when absent the total becomes the deck's planned time (so a second validation point exists at parse end, not only at `PlannedTime` construction). A slide accepts at most ONE page settings comment — a second one is a build error (the old field-wise last-wins merge could silently drop a section marker). Sections ride `DeckSettings` through every phase into `manifest.json` `sections` (always present, empty when unused); the presenter agenda measures actuals client-side (cumulative; the accumulator lives in `sectionActuals.ts` as the single measurement source, in-memory per session, persisted only under `--rehearsal` — see the rehearsal-mode bullet). Design record: `docs/specs/2026-07-04-presenter-agenda-design.md`
- Rehearsal mode (2026-07-19, Issues #288/#517–#521): `peitho present --rehearsal` persists per-section actuals plus a v2 absolute per-slide entry timeline to `.peitho/rehearsals/rehearsal-YYYYMMDD-HHMMSS.json` via incremental full snapshots. The first visible slide is entered at timer position 0 when the run starts in this presenter or the presenter adopts a timer at 0; when it adopts an already-running timer, the first entry is the current slide at the adopted position. Later slide entries and genuine revisits append `{key,index,atMs}`, reveal steps do not, and reset clears the timeline. `peitho rehearsal [--all]` prints the section/planned/actual/delta table plus a v2 slide/key/entered/visits/total table in first-visit order; an optional `(before first entry)` row accounts for an adopted timer's leading gap and the final row reconciles to `elapsedMs` (latest by default, no deck argument — records are CWD-relative like the caches); durable v1 records remain readable and print byte-identically with the section table only. Review is terminal-only by author decision (2026-07-19): rehearsal data exists to adjust timing retrospectively, the live agenda suffices mid-talk, so the presenter renders nothing rehearsal-specific and present never reads the records. The presenter ALWAYS reports (reporter emits v2 `peitho:rehearsalreport` on local start, a 5s cadence, slide change, local pause, reset (local or adopted), the first adopted start (`running` or positive elapsed time), an adopted transition to paused, close request, and window `pagehide` (covering close from another window, window close, and display swap); `rehearsalBridge` POSTs to `/rehearsal`, registering the close-request POST with `peitho:beforeclose` `waitUntil` and using `keepalive` only for the `pagehide` fallback); whether anything is persisted is decided in exactly one place, the server's `RehearsalSink` (present only with the flag — without it the server answers `{"recorded":false}`). The sink validates non-decreasing positions bounded by `elapsedMs` and every recorded index/key against the final rendered deck before writing; all violations are specific 422 responses. With a sink, every rejected POST is a terminal `LabelStyle` warning, deduplicated by reason until a successful write; without a sink rejections stay silent. Session files are reserved atomically (`create_new`, collision suffix `-2`…), first bytes written through the reserving handle (visible empty only inside the microsecond reserve-to-write window; SIGKILL there is the accepted residual), rewrites are temp+rename under the sink mutex, and `recordedAtMs` is stable per session. The filename scheme has a single parser (`parse_rehearsal_filename` → `(stamp, suffix)` ordering key); record selection reads only scheme-matching JSON files, and a corrupt/future-version record read by `peitho rehearsal` is a hard error naming the file. `RehearsalRecord` is an enum with distinct V1/V2 payloads and common timestamp/elapsed/section accessors but deliberately no enum-wide timeline accessor; `RehearsalSnapshot` is v2-only. `--rehearsal` errors on sectionless decks and with `--no-serve`; a session where the timer never starts writes no file and no directory; `.peitho/rehearsals/` never enters `dist/` or any cache. Contract types ride ts-rs. Design records: `docs/plans/2026-07-19-rehearsal-mode.md`, `docs/specs/2026-09-18-rehearsal-audio-design.md`, `docs/plans/2026-09-18-rehearsal-audio.md`
  Rehearsal audio (2026-09-18, Issues #522–#526) remains a V2-only extension: only V2 has defaulted optional typed `audio: {file,startMs}`, while durable V1 and M1-era V2 records retain their existing read behavior. Optional timer-aligned microphone capture requires `--rehearsal --audio` and a presenter view; only this explicit flag reaches the presenter as `present.json` `rehearsalAudio` because opening a microphone is a user-visible privacy effect. Because microphone permission is keyed by the complete origin, including the port, audio mode shares the stable default port 6173 with `--host`; an explicit `--port` wins and `AddrInUse` never falls back silently. Persistence authority remains solely in `RehearsalSink`, and `/rehearsal/audio` is 404 when disabled. The presenter acquires the microphone immediately, derives `MediaRecorder` state from the shell's actual timer state after each shared event, records the rounded timer position when the recorder actually starts, and appends a `REC` segment to the single timer-state pill: its dot is hollow and dim while permission is pending or the microphone is ready, pulses in the warning color while recording, and uses the pause color while paused. Any microphone, recorder, or upload failure changes the segment label to `ERR`; microphone failures use a hollow warning dot, while upload failures preserve the current recording/paused dot state. The full reason is an out-of-flow, two-line warning above the pill (and its title retains the unclamped text), so errors never change the clock row's height. In audio mode the timer cannot wrap, and the state word hides below a 440px clock-card width while the `REC`/`ERR` segment remains visible. Non-`keepalive` chunk requests time out after 10 seconds and retry; `400`, `404`, and `413` retain the head and block that take without claiming to retry until reset. Close is two-step: `peitho:beforeclose` stops the recorder, awaits the final `dataavailable`, drains both final POSTs without `keepalive`, then closes; `pagehide` remains a best-effort fallback and is the only final path that uses `keepalive`.

  `POST /rehearsal/audio?take=<id>&seq=N&startMs=M` accepts non-empty `audio/webm` chunks up to 5 MiB; all three query values are required and `seq`/`startMs` are strict u64 decimal values. Under the sink mutex, seq 0 is accepted only when the latest snapshot has a non-empty timeline; a new take at seq 0 truncates, becomes current, and stores its `startMs`, only the current take at exactly `next_seq` appends, and every other order is 409 JSON `{take,nextSeq}`. The client drops a 409 queue head only when the same take and `nextSeq == head.seq + 1` prove persistence after a lost response; it never skips a chunk. A zeroed snapshot always clears the audio latch/current take and attempts same-stem WebM cleanup while rewriting V2 with `audio: None`; cleanup failure does not undo the persisted snapshot and warns through the audio channel with the path. Snapshot and audio rejection warnings have independent deduplication slots, each cleared only by success on its own channel. A 409 warns only for a real ordering problem inside the current take: the request take equals the current take and the response is not a lost-response acknowledgement. Conflicts where no take is current or the request names a different take stay silent.

  The single filename parser returns a typed session identity whose `json_name()` and `webm_name()` produce the accepted same-stem pair. The single record reader rejects any V2 `audio.file` other than its own identity's WebM name as a corrupt-record hard error naming the JSON; `peitho rehearsal` also notes a missing named WebM and, only when the offset rounds to at least one second, prints the offset plus a `seek` column. A slide row seeks to `0:00` when audio begins during its first visit and shows `-` only when that visit ended at or before the audio start. Timeline `atMs` remains an absolute timer position; for entries at or after `audio.startMs`, the WebM seek position is `atMs - audio.startMs`, while earlier entries have no audio. Chrome's WebM has no duration metadata; `ffmpeg -i in.webm -c copy out.webm` adds it for players that require it. Rehearsal JSON/WebM files never enter `dist/` or any cache.

- Display swap (2026-07-04, Issue #108): `S` key / presenter Swap button is an escape hatch for display misidentification — each window navigates (`location.replace`) to its counterpart route, so the windows stay put and only content roles swap. Role = URL via four routes / two files: `present.html`⇄`/presenter-swapped` (slides window), `/presenter`⇄`/present-swapped` (presenter window); the swapped aliases are extensionless and dot-free so Chrome placement keys stay distinct (dot pitfall below). Sync state is an **absolute** `{"swapped":bool}` (never a toggle command — the channel coalesces), the server tracks current `index`/`swapped`, and **every** `/sync` GET response (handshake and poll) carries that state, which the client replays idempotently after each message — this per-poll replay is load-bearing for convergence (a live window that misses a coalesced-away swap never reloads, so handshake-only replay is insufficient) and is what preserves the slide index across swap navigations. UI only emits `peitho:swaprequest` (§16); the sync bridge posts/navigates. The slides page gates the shortcut on `present.json` `presenterOpen` (a solo slides window must not swap itself away). Known tradeoffs (re-measured 2026-09-18): the timer itself survives a swap — the new presenter page adopts the server-held timer state — but everything the old presenter page measured in memory starts over (agenda section actuals, and under `--rehearsal` the slide timeline, whose first entry is then seeded at the adopted position); under `--audio` the new page starts a new take that replaces the old `.webm` (`audio.startMs` = the swap position), and because the counterpart window runs in the other Chrome profile it needs its own microphone grant (denied there → `ERR mic unavailable`, and the record keeps pointing at the pre-swap take, which is then shorter than `elapsedMs`); post-swap slides sit windowed (press `f`). Chord-modified keys (meta/ctrl/alt) are ignored by all shortcuts via a shared `hasChordModifier` guard (Cmd+S/Cmd+F keep their browser meaning). Design record: `docs/plans/2026-07-04-display-swap.md`
- Layout scripts (2026-09-23, Issues #530/#629–#637, reported with working fixes by @kfly8 in kfly8/peitho#2/#3): a layout's own `<script>` runs on every surface, and `peitho:shadow-mounted` (§16, payload `{root, key, index}`) is how it reaches its slide — `document.querySelectorAll`/`MutationObserver` never cross a shadow boundary and `document.currentScript` is `null` inside a shadow root (measured). Author decisions: present runs scripts on every surface the shell mounts (slides window, presenter panes, remote preview — the mirrors mount with `inertSlides`); preview runs them on the stage only (`createStageHost` rehydrates and returns `{host, shadow}`, `createThumbHost` never rehydrates and never exposes its root — a type split, not a flag, because the flag no longer exists when the announcement fires); the event fires in every output mode so a layout never depends on the shell. **`scripts.ts` is the single implementation** of rehydration and announcement: `executeInlineScripts` re-creates each `innerHTML`-parsed (inert) script in its own namespace with `setAttributeNode(attr.cloneNode())`, wraps only classic inline scripts in an IIFE (type is a whole-string essence match after trim — a MIME parameter or whitespace-only type is not classic, so a JSON data island stays byte-identical), clears the `createElement` force-async flag unless `async` is present, copies the hidden nonce, and pauses at a parser-blocking classic `<script src>` until `load`/`error` so an inline script after a library sees it, as in a parsed document. The backlog `window.__peithoShadowRoots` holds the event's own detail objects, exists before any layout script runs, appends and never overwrites (the presenter's two panes share it), and a non-array value is a visible load error; announcements fire after the surface has applied its final layout. The distribution viewer embeds `dist/viewer.js` (an IIFE built from `viewer.ts`, drift-checked like the other bundles) inside one IIFE with the viewer code so no viewer name is a global, re-runs a slide's scripts on every visit, drops disconnected backlog entries, and does nothing on a boundary no-op; PDF export and lint embed the same bundle twice (backlog in `<head>`, announcement after the last slide and before `pdf_flatten.js`/`lint_measure.js`), take key/index from Rust-embedded JSON rather than DOM position, never re-execute scripts, and fail the command with the key when a slide section cannot be found exactly once. Accepted divergence (#647, author decision 2026-09-23: keep as is, no single execution path): because PDF/lint never rehydrate, their inline scripts are NOT scope-wrapped, so a top-level `let`/`const` shared by two slides throws there only; the guide tells authors to keep declarations inside a block. Measured harm is limited to a layout script that finds its slide via `document.currentScript` (it cannot run in present/preview anyway); the documented listener pattern is unaffected. Do not re-open this by rehydrating PDF/lint slides or by wrapping in Rust without a new author decision. Author-facing rules live in the guide (`site/content/guide/layouts.md`, "Scripts in a layout"). Design record: `docs/plans/2026-09-23-layout-scripts.md`
- Interactive slide content (2026-09-23, Issue #631): slides may hold live controls — layout HTML ships plain `<details>`/`<input>` to every output, and layout `<script>` runs in present and on the preview stage — so every shell shortcut and navigation gesture defers to slide content through ONE module, `packages/peitho-present/src/interactiveTarget.ts`: all window keydown installers (present navigation, presenter, close-on-Escape, fullscreen `f`, swap `S`, preview) check `keyBelongsToTarget` right after `hasChordModifier`, and the click guard and swipe navigation check `pointerBelongsToTarget`, always judged from `composedPath()[0]`. - Preview loop (2026-07-07, Issue #170): `peitho preview` writes only `.peitho/preview-cache/build-<generation>/`, serves `index.html` plus `preview.js`, and tracks the same inputs as `build --watch`. There is no filesystem-watcher backend (Issue #590, 2026-09-22): every 200 ms one loop captures a fingerprint snapshot of exactly the build inputs — deck, includes, and the `*.html`/`*.css`/`*.sublime-syntax` asset files the build loads (the same `collect_asset_files` rule) by content hash; referenced images and the recursive non-hidden fonts tree by full-resolution `(mtime, len)`; deck-adjacent `layouts/`/`css/`/`syntaxes/`/`fonts/` candidates with an explicit `Missing` state — so `dist/`, `--out`, `.peitho/preview-cache/`, and the code-image cache can never trigger a rebuild by construction. A changed capture is only a candidate; a rebuild fires when the next tick's capture is identical (two-capture stability: merges truncate-then-write and atomic saves, and a file still being copied rebuilds once after it settles), targets are re-resolved before the rebuild (a changed key set becomes a new candidate), and the snapshot installed afterwards is the one captured BEFORE the build, on success or failure, so a save landing mid-build is never marked consumed; the same holds for the initial build. Design record: `docs/plans/2026-09-22-issue-590-watch-same-second.md`. Each successful watch rebuild emits a fresh generation directory, swaps the server root only after emit completes, keeps the immediately previous generation for in-flight requests, prunes older generations, and increments the server-owned `/sync` `generation` absolute state (no transient reload message). Every `/sync` GET response (handshake and 200 poll) carries `generation`; the preview client handshakes before fetching content and saves `{mode,index}` in `sessionStorage` before `location.reload()` when generation changes. If the first build fails, preview still starts with an escaped error page that polls generation and reloads on the next successful build. reload and retry" (the drift guard — browser ranges come from an older generation). `slide_edit::rewrite_block` splices once and returns the candidate only when reparsing proves nothing but the text changed: slide count, sections, every other slide's key/key-source/layout/flags/notes, the target's notes/layout/flags, recursive fragment shape, editable block count and `EditableBlockKind` sequence, reveal steps, the key rule (the target key may change only when both key sources are `Derived`), AND — found by adversarial review, beyond the original plan — every other span's text byte-identical, the edited span equal to the replacement, and each target fragment's block-level pulldown event sequence unchanged (a `|` in a table cell displaced its sibling cell, and leading spaces in a tight item un-nested its child list, with every count unchanged). No input is special-cased; every refusal falls out of the comparison and is a 422 with the reason. One deliberate splice-site exception (2026-09-25, Issue #658, author decisions: H1/H2 only, H3–H6 refused, setext never converts back): an `EditableSpan` may carry parser evidence `AtxHeading { level, line }` (attachable only through `EditableSpan::atx_heading`, so it cannot ride a non-heading span), and a replacement containing a newline on such a span splices the whole heading line with `text + "\n" + "===="|"----"` (four characters: a lone `---` is the slide separator) instead of the inline span, and `rewrite_block` returns that splice range as `BlockRewrite::replaced`, which is the only thing the server passes as the origin writer's `EditableBlock` scope (restating the scope from the inline span made the outside-scope check answer 409); the reparse comparison is unchanged and still proves the result (a heading inside a blockquote or list item is refused by it). Making the newline visible is layout CSS (`white-space: pre-line`), never a backslash hard break. **Notes and slide edits use one deck-writer mutex and one origin-write function**: `DeckWriter` dispatches the closed `DeckWrite::{Note, SlideEdit}` enum behind a single mutex (only preview installs it; otherwise both routes answer 404 before content-type or body parsing), and both operations end in `write_preview_origin_rewrite` (LineMap translation → origin drift check → pure-CRLF preservation → exactly one `write_atomic`). A note may clip at a slide span's synthetic edges; an editable block must translate whole to one origin file or the save is a 409 naming the file. Neither write path triggers a rebuild — the watcher is the only trigger. `/sync` carries one more server-owned absolute state, `buildError: string | null` (the whole GET shape is the Rust-owned `peitho_core::sync::SyncResponse`): a failed watch rebuild sets it and wakes pollers without bumping `generation`, the next successful rebuild clears it together with the generation bump under one lock, `POST /sync` rejects it, and the preview shell renders it as a fixed `textContent`-only banner above the last good generation (the first-build error page is unchanged). Shell rules: one edit at a time; `old` comes from `getAttribute` (CRLF bytes round-trip through numeric character references); the editor is locked (`contenteditable="false"`) and Enter/Escape are swallowed while the POST is in flight, and a shortcut pressed then queues a transition behind that commit; every transition settles the open edit first, then notes, and a failed save blocks it; a generation reload is deferred while an edit is open or a transition is settling and released exactly once (state saved at release) on successful commit, unchanged close, or Escape; no new edit can start while a transition is settling; `pagehide` posts a dirty edit with `keepalive`; edits never enter `sessionStorage`. For checking present, a fixed `--port` + `curl POST /sync` + `screencapture -x -D <n>` is handy.

## Pitfalls (facts confirmed by measurement — no need to re-investigate)

- **SSE does not work with tiny_http**: when data_length is None, bodies below a threshold are buffered until EOF, and the chunk encoder doesn't flush small chunks either. That's why /sync uses long polling (`GET /sync?seq=N`; a GET with no query returns immediately = join handshake; every JSON GET response (handshake and 200 poll; the 30s poll timeout is an empty 204) carries `{"seq":…,"message":…,"index":…,"swapped":…,"generation":…,"session":…,"buildError":…}` (the Rust-owned `peitho_core::sync::SyncResponse`, generated into `bindings/SyncResponse.ts`) — current absolute state on top of the latest message; `session` identifies the server process instance, and /remote reloads itself when it changes across a re-handshake; `POST /sync` only accepts `{index,step}|{swapped}|{timer:{running,elapsedMs}}|{close:true}` and generation is server-internal; rehearsal snapshots do NOT ride `/sync` — the channel coalesces, so they use the separate `POST /rehearsal` endpoint, and preview note saves, inline slide edits, and whole-slide source saves use `POST /notes` / `POST /slide-edit` / `POST /slide-source`, which answer 404 under `peitho present` because only preview installs a `DeckWriter`)
- **`peitho present --host` and rehearsal audio pin the port to 6173 and never fall back** (2026-07-17 and 2026-09-18, Issues #306 and #522–#526): the fixed port keeps the QR-scanned `http://<ip>:6173/remote` URL stable for Add to Home Screen, and it keeps the presenter's complete origin stable because microphone permission is keyed by origin including the port. Resolution is pure: `Some(p)` wins, `None + (--host or --audio)` → 6173 (`STABLE_PRESENT_PORT`), and neither → `0` (random, plain local present). Silent fallback to a random port would break the relevant persistence guarantee; `AddrInUse` on the fixed port says another `peitho present` is probably running and to pass `--port`, only when the io kind matches (a stale `--host` IP raises `AddrNotAvailable`, where that advice would be wrong). Design records: `docs/plans/2026-07-17-remote-standalone.md`, `docs/specs/2026-09-18-rehearsal-audio-design.md`
- **The final MediaRecorder chunk cannot be produced from `pagehide`** (measured 2026-09-18 with Chrome's fake media device, Issues #522–#526): `dataavailable` fires asynchronously after `stop()`, and every measured close lost both the last audio chunk and final snapshot when closing relied on `pagehide`. The sync bridge therefore dispatches `peitho:beforeclose`, accepts synchronous `waitUntil(...)` registrations, waits up to 2 seconds, and only then closes; a rehearsal server keeps a 3-second shutdown grace so those POSTs can land.
- **Chrome MediaRecorder pause/resume is gapless, but its raw WebM has no duration** (measured 2026-09-18 with Chrome's fake media device, Issues #522–#526): there was no PTS gap across a 10-second wall-clock pause, audio length matched `elapsedMs - audio.startMs` within 30 ms, and a normal start measured `startMs` at approximately 1 ms. Chrome's raw WebM had no duration metadata; `ffmpeg -i in.webm -c copy out.webm` added it.
- **iOS PWA cold start reads `100dvh` as stale** (2026-07-18, Issue #309, PR #311): when the remote is launched from the Home Screen the initial dynamic-viewport height query returns a wrong value that persists until the first visualViewport event, so the remote falls back to `100vh` + a visualViewport listener for its viewport math. The landscape breakpoint (`orientation: landscape and max-height: 520px`) and `env(safe-area-inset-top/bottom)` are load-bearing across the standalone (no Safari address bar) layout; the always-reserved Status row was removed in the same PR because the Ended state is already communicated by the dim-on-end grey-out + disabled buttons (no text row is needed). Design records: `docs/plans/2026-07-17-remote-landscape.md`, `docs/plans/2026-07-18-remote-standalone-tuning.md`
- **`--host` bare picks an address, but a token after `--host` is read as the IP value** (2026-07-16, Issue #298): `peitho present --host deck.md` binds an IP called `deck.md` (which fails); use `peitho present deck.md --host` to keep the bare form. Address ranking prefers VPN (e.g. Tailscale) over other non-loopback interfaces, and the top-ranked URL is what the terminal QR code encodes. Wildcard binding is explicit via `--host 0.0.0.0` / `--host ::`
- **Flag handoff to an already-running Chrome instance only works via `--app`**: `--start-fullscreen`/`--window-position`/`--window-size` are ignored. To reliably apply them, launch a new process with a separate `--user-data-dir` (which is why slides/presenter use two instances, `~/.peitho/chrome-profile-{slides,presenter}`)
- **PDF export flattens gradients at print time**: `pdf.html` embeds a script that converts CSS gradients to Chrome-rasterized images because Type 4 shadings render pathologically slowly and incorrectly in macOS Preview.app (measured 2026-07-06). Design record: `docs/plans/2026-07-06-pdf-gradient-flatten.md`
- **PDF export flattens box-shadow at print time**: Chrome emits blurred CSS box-shadows as `/S /Luminosity` soft masks that Quartz renders as hard black rectangles, so `pdf_flatten.js` rasterizes supported shadows to RGBA PNGs for PDF export (measured 2026-07-06). Design record: `docs/plans/2026-07-06-pdf-shadow-flatten.md`
- **`--print-to-pdf` prints whenever Chrome deems the page ready — it cannot be ordered against async in-page work** (Issues #402/#408, both measured): observation-based detection cannot close that race (a stderr sentinel arrives after the bytes are on disk; artifact-marker scans false-positive on shapes the flattener deliberately skips and on `code_images` SVGs). PDF export therefore drives printing over CDP: launch with `--remote-debugging-port=0` (no `--print-to-pdf`, no `--virtual-time-budget`), poll `Runtime.evaluate` for `data-peitho-pdf-flattened` (set on both the success and top-level-catch paths of `pdf_flatten.js`), and only then call `Page.printToPDF` (`preferCSSPageSize` honors `@page`; websocket caps lifted — the base64 PDF rides one frame). `/json/list` responses must be framed by Content-Length, never by EOF (measured: the connection can stay open and an EOF read hangs, even with `Connection: close` requested); `Execution context was destroyed`/`Cannot find default execution context` during the navigate commit are transient → retry within deadline; there is NO fallback to `--print-to-pdf` (a silent fallback would reintroduce the race). Design record: `docs/plans/2026-08-05-cdp-ordered-pdf-print.md`
- **`image.decode()` hangs forever (neither resolves nor rejects) in Linux headless Chrome under `--virtual-time-budget`** (measured 2026-07-06, Issue #155): no rejection means `.catch()` never fires — the hang itself is silent, and Chrome prints the page once the virtual-time budget expires. On macOS decode just happened to finish before the budget ran out. Today only lint runs under virtual time (`lint_measure.js`); PDF export moved to CDP-ordered printing (Issue #408), where a hang in the flatten chain means the readiness attribute never appears and `peitho export pdf` fails loudly at its deadline instead of shipping an unflattened PDF. In-page print scripts still never rely on `decode()` and wait on load/error events instead (lint because of virtual time, export because a never-settling promise is a hard export failure); reintroduction is guarded by the Linux `e2e` CI job (with `PEITHO_CHROME_PATH` set explicitly so a missing Chrome panics instead of silently skipping). Design record: `docs/plans/2026-07-06-pdf-flatten-linux-decode-hang.md`
- **On macOS, Chrome's process lingers even after all windows are closed**: if the previous present instance is still holding the peitho profile, the next launch becomes a handoff and all placement flags are lost. That's why present terminates any lingering process before opening
- **Lingering Chrome processes must be terminated normally, not killed with SIGTERM**: SIGTERM registers as a crash to Chrome (`exit_type: Crashed`), triggering crash recovery on the next launch which restores the old session's windows/bounds. Using `NSRunningApplication.terminate` (in JXA this fires via **parenthesis-less** access, due to the bridge — confirmed by testing) terminates it as Normal. Note that `exit_type` always shows Crashed while running (it's written up front at launch, then flipped back to Normal on clean exit), so reading it while the process is active is meaningless. Restrict target pids to the Chrome main process (no `--type=`) from `ps` (`pgrep -f` also catches the shell itself if it contains the pattern)
- **Chrome 149 on macOS may never exit after one-shot headless work**: `--print-to-pdf` can complete its output but keep the parent process alive after waking GoogleUpdater (measured on the old export path; lint/embed still use `--print-to-pdf`-style one-shots). One-shot callers must use the shared runner (spawn + piped readers + completion predicate + timeout + kill/reap), never `Command::output()`. PDF export now prints via CDP (Issue #408): the deliverable is complete once `Page.printToPDF` returns, so post-print shutdown is best-effort — `Browser.close`, a short grace wait, then kill+reap — and never fails the export. Killing is acceptable in both shapes because these paths use throwaway temp `--user-data-dir` profiles; the SIGTERM crash-recovery warning above applies to persistent presenter profiles
- **Chrome's `--app` window position restoration breaks if the app name contains a dot**: the position is saved under `browser.app_window_placement` keyed by a URL-derived app name (host+path), but a dot in the name (as in `127.0.0.1` or `.html`) gets expanded as a pref path when written, causing a mismatch on read and preventing restoration (confirmed Chromium behavior, measured). That's why presenter opens at `http://localhost:<port>/presenter` (an extensionless route). Since the app name doesn't include the port, restoration still works even though the port changes each time
- **On the first `--app` launch with no placement flags, which display the window appears on is undetermined**: if it appears on the slides-side display, it can end up completely hidden behind the fullscreen Space (it won't even show up in CGWindowList's OnScreenOnly). That's why windowed mode only seeds `--window-position`+`--window-size` to center on the primary display when there's no saved placement or the saved position is off-screen; when there is a visible saved placement, it's left flag-free and Chrome's own restoration is trusted (the check is peitho reading the profile's Preferences). Chrome clamps partially off-screen saved bounds at launch
- **`window.getSelection()` cannot see a caret inside a shadow root** (measured in Chrome 2026-09-21, Issue #543): the range is retargeted to the shadow host, so an editor inside a slide's shadow root must resolve its range shadow-aware — `selection.getComposedRanges({shadowRoots:[root]})`, then the non-standard `shadowRoot.getSelection()`, then the document selection. The first inline-edit Shift+Enter appended the newline at the end of the text with the caret before it; jsdom cannot show this. Second half of the same measurement: a single trailing `"\n"` at the end of a `white-space: pre-wrap` block renders no line and no caret position, so at end-of-text the shell inserts a one-newline sentinel that the dirty check and the request ignore (`rewrite_block` trims edge newlines server-side anyway)
- **The first automated click after navigating an unfocused tab delivers no DOM events at all** (measured 2026-09-21 with the Chrome extension driver; not even `pointerdown` reaches a window capture listener, the click only focuses the document): when E2E-checking preview by automation, click once to focus before the click under test, or the step looks like "click does nothing"
- **Chrome restores the preview page from the back/forward cache without re-running its bootstrap** (measured 2026-09-21, Issue #546): the preview bootstrap disposes shell, keyboard, and reload handles on `pagehide` (the keepalive saves run there), so a BFCache-restored document came back visible but inert — clicks, PageDown, editing, and the `/sync` poll all dead, silently, with the navigation entry still showing the original load. A restored preview is stale anyway (generation, notes, edit annotations), so the bootstrap reloads on `pageshow` when `event.persisted`. Present, presenter, and remote do not dispose on `pagehide` and are unchanged. Design record: `docs/plans/2026-09-21-preview-bfcache-restore.md`
- **notify's `PollWatcher` truncates mtimes to whole seconds and only fires on `new.mtime > old.mtime`** (notify 8.2.0 `poll.rs`, measured 2026-09-22, Issue #590): a second save within the same second was silently missed (preview stayed stale and a source save answered the drift 409 forever), and `compare_contents` fixes that only by hashing every regular file in every registered directory five times a second — measured 23% of a core idle with a 60 MB file beside `deck.md`, e.g. the default `export pdf` output. That is why the watch loop is a peitho-owned snapshot and the `notify` crates are gone; do not reintroduce a watcher backend as a second detector or as a wake-up hint (both were built and rejected: real event batches carry directory paths, which defeat echo detection and rebuilt twice per atomic save). Installing the snapshot taken AFTER a build was also measured wrong (a save 0.15 s after the first was served in 1/6 runs): install the pre-build capture only. Accepted residual: a same-length rewrite of an image/font within one mtime granule on a whole-second-mtime filesystem
- **BroadcastChannel does not reach across different profiles**: that's why sync goes through the server (a deliberate extension from §15; the layering — DOM events bridged to a transport — remains unchanged)
- **A CLI-launched app window is closed via `window.close()`** (because it has only 1 history entry). Esc triggers `peitho:closerequest` → `{close:true}` broadcast to all windows → each closes itself → the server also unblocks and exits after a grace period
- **requestFullscreen/window.open require transient user activation**: awaiting a permission prompt in between invalidates it. In-browser window placement failed twice this way before the switch to CLI-driven placement (M8/M9/M10)
- NSScreen has a bottom-left origin. Chrome's `--window-position` uses top-left. The conversion lives in `displays.rs` (pure functions + tests against measured values)
- In vitest tests, always destroy/clean up the shell/listeners (listener contamination on the shared window causes multiple firings)
- `.peitho/present-cache/` is recreated every time (the adopted value from the §18 cache policy). `.peitho/preview-cache/` contains generation directories and swaps between them after emit completes, keeping only the current and previous generations. `dist/slides/` is also cleared on every build (to prevent stale fragments from leaking into publish). `.peitho/rehearsals/` is NOT a cache — rehearsal records are user data, never pruned automatically (delete files by hand to drop a baseline)
- **pulldown-cmark 0.10 loops forever on indented `---` dense pairs once `ENABLE_YAML_STYLE_METADATA_BLOCKS` is on** (upstream #912, fixed in 0.11.1) — that is why the workspace pins 0.13. **0.13 still tokenizes dense mid-document `---` pairs as metadata blocks** (measured; legitimate slides like `---`/`# Cfg`/`port: 8080`/`---` get swallowed), so frontmatter detection and slide splitting use two grammars: metadata-enabled only for the leading block, the legacy grammar for splitting. Do not load metadata blocks into the split grammar
- **A named ES-module import from a bundle that lacks the export fails at module instantiation** — showError never runs and the window is just black (a recurring incident class). The present/presenter entry pages therefore use a namespace import (`import * as peitho from './shell.js'`) plus feature detection, so a stale `--shell` bundle degrades to a visible error instead
- Explicit slot syntax (2026-07-05, Issue #21): when convention mapping (title/code/image/body) can't tell where content belongs — two-column layouts, multiple `blocks` slots — the author writes `::: {slot=name}` fenced blocks. The parser tokenizes them line-first (fenced-code interior excluded), produces a `FragmentKind::SlotGroup { name: ExplicitSlot, children }` in Parsed, and mapping expands the children into the named slot; SlotGroup never leaves the Mapped phase. `ExplicitSlot`'s constructor is `pub(crate)` so no consumer outside the parser can fabricate one — this preserves the invariant that convention- and author-declared routing cannot be silently interchanged. Slidev-style `<template #name>` was rejected because it would leak HTML component vocabulary into content (pillar ①). Validation is exhaustive (11 rules, all line-numbered errors): unclosed/nested/empty divs, 4+ colon fences, missing/unknown/multi attributes, invalid slot names, unknown slot names against the layout, accepts violations via existing check.rs. Design record: `docs/specs/2026-07-05-explicit-slot-syntax.md`, implementation plan: `docs/plans/2026-07-05-explicit-slot-syntax.md`
