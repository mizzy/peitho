# peitho

An HTML-native presentation tool with Markdown as the source of truth. The authoritative design reference is `docs/PEITHO_KICKOFF.md` (the kickoff spec). When in doubt about a design decision, check §18 "Undecided Items" in the spec; for new decisions not covered there, check with the author.

## Language

All written artifacts in this project must be in English. This includes: documentation (README, docs/, inline comments, commit messages), GitHub issues (titles and bodies), pull requests (titles, bodies, and review comments), and code identifiers. Do not write these in Japanese or any other language. If the author writes to you in Japanese, still produce artifacts in English.

## The three pillars (invariants that must not be broken)

1. **Separation of content and design**: Content is Markdown, design is layout HTML+CSS. Do not mix them
2. **Version-controllable HTML/CSS layouts**: The layout itself is the schema (`<slot name accepts arity>`). Do not split the contract into a separate file
3. **Type-checked slot contracts and keyed overrides**: Slot excess/deficiency, type mismatches, broken references, and unassigned content are all build errors with line numbers + help. **Silent dropping is absolutely forbidden** (never let the parser swallow unknown structures with `_ => {}`)

Other invariants:
- typestate `Parsed→Mapped→Checked→Rendered`. Phase constructors are private within the crate. An unchecked deck cannot be passed to the renderer (pinned down by a compile_fail doctest)
- Multiple layouts use hybrid dispatch (type-driven approach from §18 adopted at the author's discretion, 2026-07-03): explicit `{"layout":"name"}` > unconditional if there's only one > unique structural match. Ambiguous or zero matches are never silently resolved — they are build errors. Slides carry their own Layout from Mapped onward, so no lookup-failure path is created downstream
- Syntax highlighting is done at build time with syntect (adopted 2026-07-03). Output is spans with `hl-*` classes, colors come from the theme CSS. Custom syntaxes come from `syntaxes:` frontmatter or `syntaxes/` next to the deck and augment the built-in set. Unknown language tags are a parse-time error with a line number (no tag means plain text)
- Deck-level settings ride in YAML frontmatter at the top of the deck (author decision 2026-07-03: "zero-config, settings live in Markdown frontmatter"). Supported keys: `time` (planned presentation time, `15m`/`90s`/`1h30m`/bare integer minutes), `aspect_ratio`, `resolution` (PDF-only physical page size, `WxH` CSS px), `breaks` (single newlines in slide body Markdown render as hard line breaks when `true`), `lang` (BCP 47 deck language, default `en`, emitted as `<html lang>` on every page that renders slides — distribution index, PDF, lint, present, preview, presenter; the remote controller and preview error page stay `en`), `layouts`, `css`, `syntaxes`, `fonts`, and `code_images`. For asset keys, asset resolution is explicit frontmatter > deck-adjacent auto-detect (`layouts/` / `css/` / `syntaxes/` / `fonts/`) > built-in embed/default for layouts/css/syntaxes or no extra asset for fonts; explicit non-existent paths are line-numbered build errors, not silent fallback. Asset values may be a file or a directory: layouts/css/syntaxes read `*.html`, `*.css`, and `*.sublime-syntax` in deterministic filename order, while fonts are copied verbatim without an extension filter so `.woff2`, `.ttf`, and `@font-face` CSS files can sit side by side. The frontmatter body is restricted to flat `key:` lines, plus one nested `code_images:` mapping level (trailing style blank lines allowed); unknown keys, invalid values, markdown swallowed by a missing closing `---`, a leading `---` without valid frontmatter, and settings anywhere but the top are all line-numbered build errors with help — no silent path exists. Validation happens once at `PlannedTime`'s construction (nonzero, overflow, ≤ `Number.MAX_SAFE_INTEGER` so JSON.parse can't round it), and the validated newtype rides on `Deck<P>` through every phase; milliseconds appear only at consumption boundaries (manifest). Design records: `docs/specs/2026-07-03-time-tracking-design.md`, `docs/plans/2026-07-05-frontmatter-layouts-css.md`
- code_images renderer resolution (2026-08-05, Issues #252/#287/#395/#398/#399): Mermaid is built in via `merman`, math via `katex-rs`, and a bare `embed` block resolves exactly one typed author URL. X status URLs retain byte-identical screenshot/card paths; absent or explicit `mode=screenshot` uses the existing build-time PNG, while `mode=card` fetches raw X oEmbed JSON and produces `FragmentKind::EmbedCard { html }`. Every other HTTP(S) URL becomes a normalized `EmbedTarget::Generic`; exact or subdomain hosts of `x.com`/`twitter.com` that are not supported status URLs keep the X-form error and never reach discovery. `mode=` is X-only and is a line-numbered error on generic targets. Generic dispatch uses separate `OEmbedFetcher` operations for the discovery page, discovered JSON endpoint, and thumbnail, and X/generic paths must never touch one another's operations. Discovery is attribute-based JSON oEmbed `<link>` parsing with entity-decoded, RFC 3986-resolved hrefs; provider HTML is never retained or injected. Generic JSON and thumbnail bytes use distinct page-URL cache domains under `.peitho/embeds-cache/`; regular-file/size/magic gates, atomic writes, and self-heal apply, discovery HTML is never cached, and complete hits need neither curl nor Chrome. A generic response with a thumbnail (or a photo `url` fallback) becomes `FragmentKind::GenericEmbedCard { image: Some(_) }`; otherwise it becomes the author-approved text-card fallback with `image: None`. Both variants are `Accepts::Blocks`; the optional typed image must pass through `ImageResolver` and publish-contamination checks before rendering, and all retained strings are escaped with the normalized author URL as permalink. CLI X card misses keep the exact direct, no-redirect `publish.x.com` curl argv; generic fetches alone follow at most five HTTP(S) redirects with operation-specific caps. `dot`, `plantuml`, and every other diagram tag stay user-declared external commands. `CodeImagesConfig::renderer_for(tag)` is the single typed resolver (`External(&CodeImageCommand)` for explicit non-embed frontmatter, `ExternalEmbed(&CodeImageCommand)` for an explicit `embed` override, `BuiltinMermaid` for bare `mermaid`, `BuiltinMath` for bare `math`, `BuiltinEmbed` for bare `embed`, `None` otherwise). Both parser unknown-language validation and `code_images` transformation must go through that resolver — no tag-string carve-outs. `SvgRunner` remains only "run an external command"; external commands and built-in Mermaid use the SVG path (validate → normalize → cache → image fragment), built-in math uses `MathRenderer`/`MathOutput`, screenshot embeds use `EmbedRenderer`, and cards use typed body paths. Explicit `code_images.embed: ...` rejects `mode=` fence options; with a bare `embed` fence it receives the complete block body verbatim and returns to the external SVG/image path. Bare `true`/`false` `code_images` values remain line-numbered errors. Decks with math prepend embedded KaTeX CSS and write `katex-fonts/`; decks without math emit neither. Decks with X or generic cards prepend only the required embedded card CSS in stable order; decks without cards emit none, and decks with neither preserve existing CSS bytes.
  Embed modifiers are typed whitespace-separated `key=value` fence-info tokens. Valid X screenshot and raw oEmbed JSON cache hits need neither Chrome nor network, corrupt X cache entries self-heal, X card HTML is regenerated only from validated, escaped JSON data, and X-card-only decks never invoke Chrome.
- code_images SVG intrinsic size (2026-07-12, Issue #261): every SVG written to `.peitho/code-images-cache/` carries usable absolute `width`/`height` on the root tag — mermaid-style output (`width="100%"`, no height, viewBox only) collapses to 0×0 via `<img>` otherwise. Normalization happens once at the cache-write seam (viewBox supplies missing/unusable dimensions; graphviz output passes through byte-identical); cached files lacking the invariant are cache misses (self-heal); no-dims-no-viewBox and root-tag-not-found are distinct line-numbered build errors. Attribute names match exact case (XML semantics — browsers ignore `WIDTH`/`viewbox`, so peitho must too). User-referenced `![](foo.svg)` assets stay verbatim by design. - Agenda sections (2026-07-04): a slide's page settings comment may declare `{"section":"Name","time":"1m"}` (section and time must appear together; the marked slide starts a section that runs until the next marker). Ranges are derived at parse end; if any marker exists the first slide must carry one; when frontmatter `time` is present the section total must equal it, when absent the total becomes the deck's planned time (so a second validation point exists at parse end, not only at `PlannedTime` construction). A slide accepts at most ONE page settings comment — a second one is a build error (the old field-wise last-wins merge could silently drop a section marker). Sections ride `DeckSettings` through every phase into `manifest.json` `sections` (always present, empty when unused); the presenter agenda measures actuals client-side (cumulative; the accumulator lives in `sectionActuals.ts` as the single measurement source, in-memory per session, persisted only under `--rehearsal` — see the rehearsal-mode bullet). - Rehearsal mode (2026-07-19, Issues #288/#517–#521): `peitho present --rehearsal` persists per-section actuals plus a v2 absolute per-slide entry timeline to `.peitho/rehearsals/rehearsal-YYYYMMDD-HHMMSS.json` via incremental full snapshots. The first visible slide is entered at timer position 0 when the run starts in this presenter or the presenter adopts a timer at 0; when it adopts an already-running timer, the first entry is the current slide at the adopted position. Later slide entries and genuine revisits append `{key,index,atMs}`, reveal steps do not, and reset clears the timeline. `peitho rehearsal [--all]` prints the section/planned/actual/delta table plus a v2 slide/key/entered/visits/total table in first-visit order; an optional `(before first entry)` row accounts for an adopted timer's leading gap and the final row reconciles to `elapsedMs` (latest by default, no deck argument — records are CWD-relative like the caches); durable v1 records remain readable and print byte-identically with the section table only. Review is terminal-only by author decision (2026-07-19): rehearsal data exists to adjust timing retrospectively, the live agenda suffices mid-talk, so the presenter renders nothing rehearsal-specific and present never reads the records. The presenter ALWAYS reports (reporter emits v2 `peitho:rehearsalreport` on local start, a 5s cadence, slide change, local pause, reset (local or adopted), the first adopted start (`running` or positive elapsed time), an adopted transition to paused, close request, and window `pagehide` (covering close from another window, window close, and display swap); `rehearsalBridge` POSTs to `/rehearsal`, registering the close-request POST with `peitho:beforeclose` `waitUntil` and using `keepalive` only for the `pagehide` fallback); whether anything is persisted is decided in exactly one place, the server's `RehearsalSink` (present only with the flag — without it the server answers `{"recorded":false}`). The sink validates non-decreasing positions bounded by `elapsedMs` and every recorded index/key against the final rendered deck before writing; all violations are specific 422 responses. With a sink, every rejected POST is a terminal `LabelStyle` warning, deduplicated by reason until a successful write; without a sink rejections stay silent. Session files are reserved atomically (`create_new`, collision suffix `-2`…), first bytes written through the reserving handle (visible empty only inside the microsecond reserve-to-write window; SIGKILL there is the accepted residual), rewrites are temp+rename under the sink mutex, and `recordedAtMs` is stable per session. The filename scheme has a single parser (`parse_rehearsal_filename` → `(stamp, suffix)` ordering key); record selection reads only scheme-matching JSON files, and a corrupt/future-version record read by `peitho rehearsal` is a hard error naming the file. `RehearsalRecord` is an enum with distinct V1/V2 payloads and common timestamp/elapsed/section accessors but deliberately no enum-wide timeline accessor; `RehearsalSnapshot` is v2-only. `--rehearsal` errors on sectionless decks and with `--no-serve`; a session where the timer never starts writes no file and no directory; `.peitho/rehearsals/` never enters `dist/` or any cache. Contract types ride ts-rs. Design records: `docs/plans/2026-07-19-rehearsal-mode.md`, `docs/specs/2026-09-18-rehearsal-audio-design.md`, `docs/plans/2026-09-18-rehearsal-audio.md`
  Rehearsal audio (2026-09-18, Issues #522–#526) remains a V2-only extension: only V2 has defaulted optional typed `audio: {file,startMs}`, while durable V1 and M1-era V2 records retain their existing read behavior. Optional timer-aligned microphone capture requires `--rehearsal --audio` and a presenter view; only this explicit flag reaches the presenter as `present.json` `rehearsalAudio` because opening a microphone is a user-visible privacy effect. Because microphone permission is keyed by the complete origin, including the port, audio mode shares the stable default port 6173 with `--host`; an explicit `--port` wins and `AddrInUse` never falls back silently. Persistence authority remains solely in `RehearsalSink`, and `/rehearsal/audio` is 404 when disabled. The presenter acquires the microphone immediately, derives `MediaRecorder` state from the shell's actual timer state after each shared event, records the rounded timer position when the recorder actually starts, and visibly reports `… REC`, `○ REC`, `● REC`, `❙❙ REC`, microphone failure, retained-chunk upload retry, or a permanent upload failure. An upload failure is appended to the current capture glyph; only microphone/recorder failure replaces it. Non-`keepalive` chunk requests time out after 10 seconds and retry; `400`, `404`, and `413` retain the head and block that take without claiming to retry until reset. Close is two-step: `peitho:beforeclose` stops the recorder, awaits the final `dataavailable`, drains both final POSTs without `keepalive`, then closes; `pagehide` remains a best-effort fallback and is the only final path that uses `keepalive`.

  `POST /rehearsal/audio?take=<id>&seq=N&startMs=M` accepts non-empty `audio/webm` chunks up to 5 MiB; all three query values are required and `seq`/`startMs` are strict u64 decimal values. Under the sink mutex, seq 0 is accepted only when the latest snapshot has a non-empty timeline; a new take at seq 0 truncates, becomes current, and stores its `startMs`, only the current take at exactly `next_seq` appends, and every other order is 409 JSON `{take,nextSeq}`. The client drops a 409 queue head only when the same take and `nextSeq == head.seq + 1` prove persistence after a lost response; it never skips a chunk. A zeroed snapshot always clears the audio latch/current take and attempts same-stem WebM cleanup while rewriting V2 with `audio: None`; cleanup failure does not undo the persisted snapshot and warns through the audio channel with the path. Snapshot and audio rejection warnings have independent deduplication slots, each cleared only by success on its own channel. A 409 warns only for a real ordering problem inside the current take: the request take equals the current take and the response is not a lost-response acknowledgement. Conflicts where no take is current or the request names a different take stay silent.

  The single filename parser returns a typed session identity whose `json_name()` and `webm_name()` produce the accepted same-stem pair. The single record reader rejects any V2 `audio.file` other than its own identity's WebM name as a corrupt-record hard error naming the JSON; `peitho rehearsal` also notes a missing named WebM and, only when the offset rounds to at least one second, prints the offset plus a `seek` column. A slide row seeks to `0:00` when audio begins during its first visit and shows `-` only when that visit ended at or before the audio start. Timeline `atMs` remains an absolute timer position; for entries at or after `audio.startMs`, the WebM seek position is `atMs - audio.startMs`, while earlier entries have no audio. Chrome's WebM has no duration metadata; `ffmpeg -i in.webm -c copy out.webm` adds it for players that require it. Rehearsal JSON/WebM files never enter `dist/` or any cache.

- Display swap (2026-07-04, Issue #108): `S` key / presenter Swap button is an escape hatch for display misidentification — each window navigates (`location.replace`) to its counterpart route, so the windows stay put and only content roles swap. Role = URL via four routes / two files: `present.html`⇄`/presenter-swapped` (slides window), `/presenter`⇄`/present-swapped` (presenter window); the swapped aliases are extensionless and dot-free so Chrome placement keys stay distinct (dot pitfall below). Sync state is an **absolute** `{"swapped":bool}` (never a toggle command — the channel coalesces), the server tracks current `index`/`swapped`, and **every** `/sync` GET response (handshake and poll) carries that state, which the client replays idempotently after each message — this per-poll replay is load-bearing for convergence (a live window that misses a coalesced-away swap never reloads, so handshake-only replay is insufficient) and is what preserves the slide index across swap navigations. UI only emits `peitho:swaprequest` (§16); the sync bridge posts/navigates. The slides page gates the shortcut on `present.json` `presenterOpen` (a solo slides window must not swap itself away). Known tradeoffs: the presenter timer resets on swap; post-swap slides sit windowed (press `f`). Chord-modified keys (meta/ctrl/alt) are ignored by all shortcuts via a shared `hasChordModifier` guard (Cmd+S/Cmd+F keep their browser meaning). Design record: `docs/plans/2026-07-04-display-swap.md`

- Lint font-size waiver (2026-09-11): `peitho lint` reads the CSS custom property `--peitho-lint-min-font-size` on each measured text node's parent (`lint_measure.js`); when set, that value replaces the 24pt floor for the text. The waiver lives in layout CSS by design (the font size is decided there, and custom properties inherit, so slot / keyed-slide / deck granularity comes from the existing cascade with no Markdown syntax or pipeline field). Waived text at or above its floor is a `note:` (visible, exit code unaffected, same principle as the #462 ellipsis note); text below its floor is a warning naming the floor. JS keeps one representative per slide and always prefers a violation over an allowed node so a violation is never hidden; Rust makes the final call on rounded pt so message and decision agree. The value grammar is closed: `Npt`, `Npx`, or `0`; anything else rides `fontSizeWaiverError` and is a hard lint error naming the slide and value (no silent path). Design record: `docs/plans/2026-09-11-lint-font-size-waiver.md`
- External links (2026-09-01, Issue #455): every slot's HTML passes exactly once through `open_external_links_in_new_tab` at the `render_slot` seam (a lol_html `a[href]` pass): an `http:`/`https:` href (ASCII case-insensitive) gains `target="_blank"`, plus `rel="noopener"` only when the anchor has no `rel` (embed-card anchors keep their `noopener noreferrer`); relative, `#fragment`, `mailto:`/`tel:`, and every other href are untouched, layout HTML is never rewritten, and lol_html emits untouched content verbatim, so decks without links build byte-identically. There is no opt-out. A lol_html failure there is an internal render error at the slot's first fragment line. `createClickNavigationGuard` (present canvas, preview grid tiles, and the inline copy in `render_distribution_index`) ignores a click whose `composedPath()[0]` is inside an `<a>` (the canvas is a shadow root, so `event.target` alone would miss), so a link click never also advances the deck. `render_heading_inline` routes through `normalize_markdown_event`, so HTML comments in headings are dropped like body comments and never reach `dist/`. Design record: `docs/plans/2026-09-01-external-links-new-tab.md`
- Single source for the contract: domain types are authoritative in peitho-core (Rust). TS types are generated into `bindings/*.ts` via ts-rs and committed. CI checks for drift
- §16 event contract: only the shell executes transitions. UI components only emit request events like `peitho:navigate`/`peitho:timercontrol`. The slide body itself has no knowledge of the shell's existence
- Do not mix the presentation shell or notes into distributed artifacts (dist/) (publish gatekeeps this with a contamination check)

## Pitfalls (facts confirmed by measurement — no need to re-investigate)

- **SSE does not work with tiny_http**: when data_length is None, bodies below a threshold are buffered until EOF, and the chunk encoder doesn't flush small chunks either. That's why /sync uses long polling (`GET /sync?seq=N`; a GET with no query returns immediately = join handshake; every JSON GET response (handshake and 200 poll; the 30s poll timeout is an empty 204) carries `{"seq":…,"message":…,"index":…,"swapped":…,"generation":…,"session":…}` — current absolute state on top of the latest message; `session` identifies the server process instance, and /remote reloads itself when it changes across a re-handshake; `POST /sync` only accepts `{index,step}|{swapped}|{timer:{running,elapsedMs}}|{close:true}` and generation is server-internal; rehearsal snapshots do NOT ride `/sync` — the channel coalesces, so they use the separate `POST /rehearsal` endpoint, and preview note saves use `POST /notes`, which answers 404 under `peitho present` because only preview installs a `NotesWriter`)
- **`peitho present --host` and rehearsal audio pin the port to 6173 and never fall back** (2026-07-17 and 2026-09-18, Issues #306 and #522–#526): the fixed port keeps the QR-scanned `http://<ip>:6173/remote` URL stable for Add to Home Screen, and it keeps the presenter's complete origin stable because microphone permission is keyed by origin including the port. Resolution is pure: `Some(p)` wins, `None + (--host or --audio)` → 6173 (`STABLE_PRESENT_PORT`), and neither → `0` (random, plain local present). Silent fallback to a random port would break the relevant persistence guarantee; `AddrInUse` on the fixed port says another `peitho present` is probably running and to pass `--port`, only when the io kind matches (a stale `--host` IP raises `AddrNotAvailable`, where that advice would be wrong). Design records: `docs/plans/2026-07-17-remote-standalone.md`, `docs/specs/2026-09-18-rehearsal-audio-design.md`
- **The final MediaRecorder chunk cannot be produced from `pagehide`** (measured 2026-09-18 with Chrome's fake media device, Issues #522–#526): `dataavailable` fires asynchronously after `stop()`, and every measured close lost both the last audio chunk and final snapshot when closing relied on `pagehide`. The sync bridge therefore dispatches `peitho:beforeclose`, accepts synchronous `waitUntil(...)` registrations, waits up to 2 seconds, and only then closes; a rehearsal server keeps a 3-second shutdown grace so those POSTs can land.
- **Chrome MediaRecorder pause/resume is gapless, but its raw WebM has no duration** (measured 2026-09-18 with Chrome's fake media device, Issues #522–#526): there was no PTS gap across a 10-second wall-clock pause, audio length matched `elapsedMs - audio.startMs` within 30 ms, and a normal start measured `startMs` at approximately 1 ms. Chrome's raw WebM had no duration metadata; `ffmpeg -i in.webm -c copy out.webm` added it.
- **iOS PWA cold start reads `100dvh` as stale** (2026-07-18, Issue #309, PR #311): when the remote is launched from the Home Screen the initial dynamic-viewport height query returns a wrong value that persists until the first visualViewport event, so the remote falls back to `100vh` + a visualViewport listener for its viewport math. The landscape breakpoint (`orientation: landscape and max-height: 520px`) and `env(safe-area-inset-top/bottom)` are load-bearing across the standalone (no Safari address bar) layout; the always-reserved Status row was removed in the same PR because the Ended state is already communicated by the dim-on-end grey-out + disabled buttons (no text row is needed). Design records: `docs/plans/2026-07-17-remote-landscape.md`, `docs/plans/2026-07-18-remote-standalone-tuning.md`
- **`--host` bare picks an address, but a token after `--host` is read as the IP value** (2026-07-16, Issue #298): `peitho present --host deck.md` binds an IP called `deck.md` (which fails); use `peitho present deck.md --host` to keep the bare form. Address ranking prefers VPN (e.g. Tailscale) over other non-loopback interfaces, and the top-ranked URL is what the terminal QR code encodes. Wildcard binding is explicit via `--host 0.0.0.0` / `--host ::`
- **Flag handoff to an already-running Chrome instance only works via `--app`**: `--start-fullscreen`/`--window-position`/`--window-size` are ignored. To reliably apply them, launch a new process with a separate `--user-data-dir` (which is why slides/presenter use two instances, `~/.peitho/chrome-profile-{slides,presenter}`)
- **PDF export flattens gradients at print time**: `pdf.html` embeds a script that converts CSS gradients to Chrome-rasterized images because Type 4 shadings render pathologically slowly and incorrectly in macOS Preview.app (measured 2026-07-06). Design record: `docs/plans/2026-07-06-pdf-gradient-flatten.md`
- **PDF export flattens box-shadow at print time**: Chrome emits blurred CSS box-shadows as `/S /Luminosity` soft masks that Quartz renders as hard black rectangles, so `pdf_flatten.js` rasterizes supported shadows to RGBA PNGs for PDF export (measured 2026-07-06). Design record: `docs/plans/2026-07-06-pdf-shadow-flatten.md`
- **`--print-to-pdf` prints whenever Chrome deems the page ready — it cannot be ordered against async in-page work** (Issues #402/#408, both measured): observation-based detection cannot close that race (a stderr sentinel arrives after the bytes are on disk; artifact-marker scans false-positive on shapes the flattener deliberately skips and on `code_images` SVGs). PDF export therefore drives printing over CDP: launch with `--remote-debugging-port=0` (no `--print-to-pdf`, no `--virtual-time-budget`), poll `Runtime.evaluate` for `data-peitho-pdf-flattened` (set on both the success and top-level-catch paths of `pdf_flatten.js`), and only then call `Page.printToPDF` (`preferCSSPageSize` honors `@page`; websocket caps lifted — the base64 PDF rides one frame). `/json/list` responses must be framed by Content-Length, never by EOF (measured: the connection can stay open and an EOF read hangs, even with `Connection: close` requested); `Execution context was destroyed`/`Cannot find default execution context` during the navigate commit are transient → retry within deadline; there is NO fallback to `--print-to-pdf` (a silent fallback would reintroduce the race). Design record: `docs/plans/2026-08-05-cdp-ordered-pdf-print.md`
- **`image.decode()` hangs forever (neither resolves nor rejects) in Linux headless Chrome under `--virtual-time-budget`** (measured 2026-07-06, Issue #155): no rejection means `.catch()` never fires — the hang itself is silent, and Chrome prints the page once the virtual-time budget expires. On macOS decode just happened to finish before the budget ran out. Today only lint runs under virtual time (`lint_measure.js`); PDF export moved to CDP-ordered printing (Issue #408), where a hang in the flatten chain means the readiness attribute never appears and `peitho export pdf` fails loudly at its deadline instead of shipping an unflattened PDF. In-page print scripts still never rely on `decode()` and wait on load/error events instead (lint because of virtual time, export because a never-settling promise is a hard export failure); reintroduction is guarded by the Linux `e2e` CI job (with `PEITHO_CHROME_PATH` set explicitly so a missing Chrome panics instead of silently skipping). Design record: `docs/plans/2026-07-06-pdf-flatten-linux-decode-hang.md`
- **On macOS, Chrome's process lingers even after all windows are closed**: if the previous present instance is still holding the peitho profile, the next launch becomes a handoff and all placement flags are lost. That's why present terminates any lingering process before opening
- **Lingering Chrome processes must be terminated normally, not killed with SIGTERM**: SIGTERM registers as a crash to Chrome (`exit_type: Crashed`), triggering crash recovery on the next launch which restores the old session's windows/bounds. Using `NSRunningApplication.terminate` (in JXA this fires via **parenthesis-less** access, due to the bridge — confirmed by testing) terminates it as Normal. Note that `exit_type` always shows Crashed while running (it's written up front at launch, then flipped back to Normal on clean exit), so reading it while the process is active is meaningless. Restrict target pids to the Chrome main process (no `--type=`) from `ps` (`pgrep -f` also catches the shell itself if it contains the pattern)
- **Chrome 149 on macOS may never exit after one-shot headless work**: `--print-to-pdf` can complete its output but keep the parent process alive after waking GoogleUpdater (measured on the old export path; lint/embed still use `--print-to-pdf`-style one-shots). One-shot callers must use the shared runner (spawn + piped readers + completion predicate + timeout + kill/reap), never `Command::output()`. PDF export now prints via CDP (Issue #408): the deliverable is complete once `Page.printToPDF` returns, so post-print shutdown is best-effort — `Browser.close`, a short grace wait, then kill+reap — and never fails the export. Killing is acceptable in both shapes because these paths use throwaway temp `--user-data-dir` profiles; the SIGTERM crash-recovery warning above applies to persistent presenter profiles
- **Chrome's `--app` window position restoration breaks if the app name contains a dot**: the position is saved under `browser.app_window_placement` keyed by a URL-derived app name (host+path), but a dot in the name (as in `127.0.0.1` or `.html`) gets expanded as a pref path when written, causing a mismatch on read and preventing restoration (confirmed Chromium behavior, measured). That's why presenter opens at `http://localhost:<port>/presenter` (an extensionless route). Since the app name doesn't include the port, restoration still works even though the port changes each time
- **On the first `--app` launch with no placement flags, which display the window appears on is undetermined**: if it appears on the slides-side display, it can end up completely hidden behind the fullscreen Space (it won't even show up in CGWindowList's OnScreenOnly). That's why windowed mode only seeds `--window-position`+`--window-size` to center on the primary display when there's no saved placement or the saved position is off-screen; when there is a visible saved placement, it's left flag-free and Chrome's own restoration is trusted (the check is peitho reading the profile's Preferences). Chrome clamps partially off-screen saved bounds at launch
- **BroadcastChannel does not reach across different profiles**: that's why sync goes through the server (a deliberate extension from §15; the layering — DOM events bridged to a transport — remains unchanged)
- **A CLI-launched app window is closed via `window.close()`** (because it has only 1 history entry). Esc triggers `peitho:closerequest` → `{close:true}` broadcast to all windows → each closes itself → the server also unblocks and exits after a grace period
- **requestFullscreen/window.open require transient user activation**: awaiting a permission prompt in between invalidates it. In-browser window placement failed twice this way before the switch to CLI-driven placement (M8/M9/M10)
- NSScreen has a bottom-left origin. Chrome's `--window-position` uses top-left. The conversion lives in `displays.rs` (pure functions + tests against measured values)
- In vitest tests, always destroy/clean up the shell/listeners (listener contamination on the shared window causes multiple firings)
- `.peitho/present-cache/` is recreated every time (the adopted value from the §18 cache policy). `.peitho/preview-cache/` contains generation directories and swaps between them after emit completes, keeping only the current and previous generations. `dist/slides/` is also cleared on every build (to prevent stale fragments from leaking into publish). `.peitho/rehearsals/` is NOT a cache — rehearsal records are user data, never pruned automatically (delete files by hand to drop a baseline)
- **pulldown-cmark 0.10 loops forever on indented `---` dense pairs once `ENABLE_YAML_STYLE_METADATA_BLOCKS` is on** (upstream #912, fixed in 0.11.1) — that is why the workspace pins 0.13. **0.13 still tokenizes dense mid-document `---` pairs as metadata blocks** (measured; legitimate slides like `---`/`# Cfg`/`port: 8080`/`---` get swallowed), so frontmatter detection and slide splitting use two grammars: metadata-enabled only for the leading block, the legacy grammar for splitting. Do not load metadata blocks into the split grammar
- **A named ES-module import from a bundle that lacks the export fails at module instantiation** — showError never runs and the window is just black (a recurring incident class). The present/presenter entry pages therefore use a namespace import (`import * as peitho from './shell.js'`) plus feature detection, so a stale `--shell` bundle degrades to a visible error instead
- Explicit slot syntax (2026-07-05, Issue #21): when convention mapping (title/code/image/body) can't tell where content belongs — two-column layouts, multiple `blocks` slots — the author writes `::: {slot=name}` fenced blocks. The parser tokenizes them line-first (fenced-code interior excluded), produces a `FragmentKind::SlotGroup { name: ExplicitSlot, children }` in Parsed, and mapping expands the children into the named slot; SlotGroup never leaves the Mapped phase. `ExplicitSlot`'s constructor is `pub(crate)` so no consumer outside the parser can fabricate one — this preserves the invariant that convention- and author-declared routing cannot be silently interchanged. Slidev-style `<template #name>` was rejected because it would leak HTML component vocabulary into content (pillar ①). Validation is exhaustive (11 rules, all line-numbered errors): unclosed/nested/empty divs, 4+ colon fences, missing/unknown/multi attributes, invalid slot names, unknown slot names against the layout, accepts violations via existing check.rs. Design record: `docs/specs/2026-07-05-explicit-slot-syntax.md`, implementation plan: `docs/plans/2026-07-05-explicit-slot-syntax.md`
