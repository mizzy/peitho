# Landing page: AI write-and-fix loop

## Goal

The landing page describes the pillars but never says how the author actually
uses peitho: an AI writes the deck and the layouts, and the build and lint
diagnostics drive its fixes. Three gaps, all from outside feedback on the site:

1. The AI loop is not mentioned at all.
2. The core idea (layout as schema) is described in prose only; there is no
   concrete contract → content → error → slide example.
3. It is not clear what `peitho build` guarantees versus what `peitho lint`
   checks, and the "no HTML in Markdown" rule is not stated.

## Changes

- `site/content/_index.md`
  - New first section "Write with AI, fix from diagnostics" (rows): contracts
    to write against, diagnostics to fix from, no HTML escape hatch.
  - New section "From contract to slide" (new `panels` shape): the built-in
    `title-body-code.html` slot lines, a `deck.md` slide with two code blocks,
    the real `peitho build` error (captured from the current binary), and the
    fixed slide, shown with the existing `minimal` deck screenshot
    (`/deck-shots/minimal.png`, already generated by `make demo-screenshots`).
  - New section "What each check catches" (rows): build = structure,
    lint = rendering, preview = the author's eyes.
- `site/templates/index.html`: a `panels` section shape. Each panel has a
  `label` plus exactly one of `markdown` (fenced code, or a raw `<pre>` for terminal output colored like the CLI's `error:`/`help:` labels, rendered through the `markdown` filter so it gets the site's syntax highlighting) or `deck_shot` (+ `alt`); unknown keys and
  both/neither are build failures, like the other shapes.
- `site/static/site.css`: `.panels` as one column (the landing column is too narrow for two code panels side by side), with wrapping code so the error line is never clipped.
